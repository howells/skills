# Returned content

Use when a page returns images, recommendations, search results or generated artefacts, or the user says to inspect every example. A control that works and an output that is useful are separate claims.

- **Define the set first.** List the requested cases from the collection's actual membership, empty and unavailable ones included. For an open-ended search, state the query, filters and snapshot instead of inventing a total.
- **Loaded, captured and inspected are different.** A returned result, a screenshot that exists, and content you actually opened and looked at are three separate facts. Metadata, filenames, counts and passing requests never stand in for viewing the imagery.
- **Judge against the user's goal.** State the expected result first: selecting a material should return imagery suitable for that material and use, not merely a non-empty response with the right label.
- **Look at the real thing.** Open full-size crops when detail, finish, scale or aspect ratio matters. Contact sheets help with large sets; inspect every sheet, then open ambiguous or small examples individually. For generated output, inspect what the user receives, not the success status.
- **Keep presentation and relevance apart.** A broken thumbnail and an irrelevant match have different causes even when they coincide.
- **Report against the denominator.** For example: "34 requested; 34 loaded, 26 visually inspected, 8 not inspected (IDs …)." A sample supports findings about that sample, never "all checked". When the user asked for all of them, keep going until they are done or a concrete access limit stops you.
