# Lane D — Forms

Sweep in order of revenue and trust impact: auth and checkout first, then creation flows, then settings. Deep form work belongs to `chiaroscuro`. (Label association is A4, colour-only errors A7, 16px inputs C3, touch autofocus C13 — count each once.)

- **D1. Submission cannot double-fire (BLOCKER)** — Hunt: submit handlers without `isSubmitting`/`isPending`/`useFormStatus`; `<button type="submit">` without `disabled`; async `onClick` on Pay/Create/Send/Invite/Delete. Fix: disable during flight, keep button width stable, re-enable in `finally`.
- **D2. Inputs live in a `<form>` (BLOCKER on auth/checkout, SHOULD FIX otherwise)** — Hunt: inputs with sibling click-submit button and no `<form onSubmit>`; non-submit buttons inside `<form>` missing `type="button"` (otherwise Cancel submits). Support `Cmd/Ctrl+Enter` on textareas where appropriate.
- **D3. Failed submits explain and preserve input (BLOCKER)** — Hunt: `catch` that only logs; `fetch` without `.ok` check; `reset()` called before response succeeds; missing `finally` to clear loading. Fix: keep typed values, re-enable button, render a recovery message (and field-level server errors next to their fields).
- **D4. Validate late, clear early (SHOULD FIX)** — Hunt: validation on every keystroke before first blur/submit (`mode: "onChange"`). Fix: validate on blur/submit (`mode: "onTouched"` / `"onBlur"`), then re-validate on change (`reValidateMode: "onChange"`).
- **D5. Errors sit next to their field and name the fix (SHOULD FIX)** — Hunt: top-only error banners; vague strings ("Invalid input", "Required"). Colocate with `aria-describedby` and move focus to the first invalid field on failed submit.
- **D6. Right `type` and `autocomplete` (SHOULD FIX)** — Hunt: `type="text"` on email/tel/url/search; missing `autocomplete` on `current-password`, `new-password`, `one-time-code`; `autocomplete="off"` on identity/address/payment fields. Put `spellcheck="false"`, `autocomplete="off"` and `data-1p-ignore` only on non-credential fields (search, slugs, API keys).
- **D7. Destructive actions confirm or undo (BLOCKER if irreversible with no undo, SHOULD FIX otherwise)** — Hunt: `delete*`/`remove*`/`revoke*`/`cancel*` wired directly; `window.confirm()`; destructive button styled like primary. Use the project's alert dialog with an explicit action label ("Delete project"); if none exists, put on human list.
- **D8. Buttons respond on press (SHOULD FIX)** — Hunt: shared `Button` with hover but no `:active` (`active:scale-[0.97]`, never below `0.95`).
- **D9. No dead zones in checkbox/radio rows (SHOULD FIX)** — Hunt: `<input type="checkbox|radio">` with sibling text outside `<label>`. Wrap control and label text in one `<label>` so the gap is clickable.
- **D10. Input decorations overlay the input (SHOULD FIX)** — Hunt: bordered wrapper with sibling icon + borderless input (clicking the icon misses the input). Position icons absolutely with padding on the input; `pointer-events-none` on decorative icons, refocus input on clickable clear buttons.
- **D11. Prefill known values (POLISH)** — Hunt: edit forms with empty `defaultValue`; invite signups ignoring `?email=`.
- **D12. Protect long unsaved work (POLISH)** — Hunt: multi-step flows or editors with no `beforeunload` dirty guard or draft persistence.
- **D13. Device check (always)** — Put on device list per critical form: complete keyboard-only, submit offline to verify values survive and error shows, double-click submit and confirm one network request, test autofill/1Password, and verify no zoom on iPhone.
