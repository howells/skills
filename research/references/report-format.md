# Report format

One Markdown document that answers the question on its own, even when it extends an earlier report. Use this for standard and deep work; a Linear comment keeps the same order, shorter.

```markdown
# {The question, answered in a plain phrase}

**Bottom line.** {The answer in two to five sentences: the verdict, the main reason, what to do next.}

What changed: {only when extending an earlier report; one line}

## {A finding stated as a claim}

{Prose or a table, whichever the material is. Links beside the claims they support.}

## {Next finding}

## How far to trust this

| Claim | Basis |
| --- | --- |
| {claim} | Verified on a primary page |
| {claim} | Read via search summary only |
| {claim} | Inference from {which findings} |

## Open questions

- {What is still unknown, and what would settle it}
```

- Lead with the verdict. Take a position the evidence supports; don't survey.
- Use tables wherever the data is tabular: comparisons, prices, capabilities by option.
- Cut any claim that lacks a source URL in the notes, or move it to Open questions.
- Name disagreements in the finding where they matter, with the stronger source.
- Date volatile facts in the text.
- Write for Daniel acting on it, not for completeness: a short report with five sourced claims beats a long one with twenty unsourced.
